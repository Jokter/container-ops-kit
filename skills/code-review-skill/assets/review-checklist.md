# 代码检视快速检查清单

供代码检视时快速查阅的检查清单。

## 检视准备（2 分钟）

- [ ] 阅读合并请求描述和关联问题
- [ ] 检查变更规模（理想情况下少于 400 行）
- [ ] 确认 CI/CD 状态，检查测试是否通过
- [ ] 理解业务需求

## 架构与设计（5 分钟）

- [ ] 方案适合解决当前问题
- [ ] 已阅读变更涉及的业务链路和相关模块，符合现有架构
- [ ] 设计建议指出具体维护成本，并比较简单复用与抽象成本
- [ ] 不存在更简单的实现方式
- [ ] 能否支持规模增长？
- [ ] 变更位于适当位置

## 逻辑与正确性（10 分钟）

- [ ] 已处理边界情况
- [ ] 已检查 null/undefined
- [ ] 已检查差一错误
- [ ] 已考虑竞态条件
- [ ] 异常处理完整
- [ ] 使用了正确的数据类型

## 安全性（5 分钟）

- [ ] 未硬编码密钥或其他秘密信息
- [ ] 已校验或净化输入
- [ ] 已防范 SQL 注入
- [ ] 已防范 XSS
- [ ] 已执行授权检查
- [ ] 已保护敏感数据

## 性能（3 分钟）

- [ ] 已追到实际 SQL/ORM，检查查询条件、分页、批次及事务范围
- [ ] 已检查循环查询、大 IN、排序聚合的规模风险及已有保护
- [ ] 已分析规模增长时的调用次数、并发/排队、全量汇总内存和耗时
- [ ] 未把未知索引、数据规模或固定阈值当作缺陷依据
- [ ] 不存在内存泄漏
- [ ] 已在适当场景考虑缓存

## 测试（5 分钟）

- [ ] 新增代码具有测试
- [ ] 已测试边界情况
- [ ] 已测试异常情况
- [ ] 测试易于阅读
- [ ] 测试结果具有确定性

## 代码质量（3 分钟）

- [ ] 变量和函数命名清晰
- [ ] 不存在重复代码
- [ ] 函数只承担一项职责
- [ ] 复杂代码附有注释
- [ ] 不存在魔法数字

## 文档（2 分钟）

- [ ] 公共 API 具有文档
- [ ] 已按需更新 README
- [ ] 已注明不兼容变更
- [ ] 已解释复杂逻辑

---

## 提交意见前

- [ ] 意见有具体代码位置、观察到的现象、触发条件/影响、需要开发确认的事项
- [ ] 已检查调用方限制与已有保护；保护有效时不重复提出疑点
- [ ] 未要求先掌握生产数据才能提问，未知条件明确为待确认
- [ ] 一个根因一条意见，历史意见不因行号或措辞变化而重复
- [ ] 设计建议有实际收益，不为模式或代码评选增加复杂度
- [ ] 无问题时不凑意见，回复“收到”不当作修复，解释充分可以人工确认关闭

## 严重程度标记

| 标记 | 含义 | 处理方式 |
|-------|---------|--------|
| 🔴 `[blocking]` | 必须修复 | 阻塞合入 |
| 🟡 `[important]` | 应当修复 | 如有异议，进行讨论 |
| 🟢 `[nit]` | 可选改进 | 不阻塞合入 |
| 💡 `[suggestion]` | 替代方案 | 酌情考虑 |
| 📚 `[learning]` | 知识分享 | 无需采取行动 |
| 🎉 `[praise]` | 实现良好 | 给予肯定 |

---

## 决策矩阵

| 情况 | 决策 |
|-----------|----------|
| 严重安全问题 | 🔴 阻塞合入，立即修复 |
| 不兼容变更未提供迁移方案 | 🔴 阻塞合入 |
| 缺少异常处理 | 🟡 应当修复 |
| 新代码没有测试 | 🟡 应当修复 |
| 风格偏好 | 🟢 不阻塞合入 |
| 小幅命名改进 | 🟢 不阻塞合入 |
| 代码可工作但技巧性过强 | 💡 建议简化 |

---

## 时间预算

此清单面向**轻量快速检视**。如需完整的架构和性能分析，请使用 [SKILL.md](../SKILL.md) 中的四阶段流程（19～36 分钟）。小型变更通常接近各阶段耗时下限，大型变更接近上限。

| 变更规模 | 快速检视 | 完整检视（四阶段） |
|---------|-------------|----------------------|
| 少于 100 行 | 10～15 分钟 | 约 19～28 分钟 |
| 100～400 行 | 20～40 分钟 | 约 28～36 分钟 |
| 超过 400 行 | 建议拆分 | 建议拆分 |

---

## 警示信号

留意以下模式：

- 生产代码中的 `// TODO`
- 遗留在代码中的 `console.log`
- 被注释掉的代码
- TypeScript 中的 `any` 类型
- 空的 catch 块
- Rust 生产代码中的 `unwrap()`
- 魔法数字或魔法字符串
- 复制粘贴的代码块
- 缺少空值检查
- 硬编码 URL 或凭据
