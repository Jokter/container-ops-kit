# Container Ops Kit

Container Ops Kit 统一管理构建、部署与容器运维过程中使用的环境、任务和产物。

## 领域语言

**构建环境**：
构建任务必须选择的 Linux 远程环境。每个构建环境归属一个发布版本，固定使用 `huawei` 用户，并独立维护 IP、SSH 端口、密码、工作目录和系统架构。
_避免使用_：构建资源、编译机器

**容器环境**：
部署与容器运维使用的 Linux 远程环境。每个容器环境归属一个发布版本，唯一 OM 节点就是远程主机，固定提供 `sopuser`、`root` 两个 SSH 用户并分别维护密码，同时维护 OM 节点 IP、SSH 端口、工作目录、系统架构。业务面和管理面连接配置均可选；填写时需要同时提供完整 HTTP(S) 地址、账号和密码。
_避免使用_：部署资源、OM 环境

**发布版本**：
一年内的产品发布批次。版本编号与展示名称分别维护，例如 `R27C00` 展示为 `27A`，`R27C10` 展示为 `27B`；一个发布版本可以包含多个环境，每个环境只归属一个发布版本。
_避免使用_：工具链版本、配置版本

**系统架构**：
Linux 远程环境的指令集架构，取值为 `x86_64` 或 `aarch64`，界面分别显示为 x86 和 ARM。
_避免使用_：CPU 型号、CPU 信息

**连接测试**：
使用环境自身的 SSH 用户、IP、端口和密码验证能否建立 SSH 连接。构建环境固定使用 `huawei`；容器环境单次测试由用户选择 `sopuser` 或 `root`，批量测试使用 `sopuser`。连接测试不检查工作目录、系统架构、业务面、管理面或其他软件。

**CBB-Web-Dev 仓**：
参与构建的固定业务代码仓库。仓库地址由系统定义，构建任务只选择分支。
_避免使用_：可编辑业务仓、目标模块

**构建分支**：
分别绑定 CBB-Web-Dev 和 ArchDesign 的单一分支；未显式填写时使用 `master`。
_避免使用_：全局业务分支、多选分支

**构建任务**：
在一个构建环境中检出并构建 CBB-Web-Dev、ArchDesign 的一次运行时执行。单分支任务执行一组分支；双分支任务并发执行基准版本和验证版本，双方均成功后才对比 ArchDesign。任务状态和日志不持久化，服务重启后清空。

**构建产物**：
单分支构建成功后生成且可供后续部署选择的不可变结果。它记录构建环境、模块、两个仓库分支以及远端模块和 Chart 根目录。

**构建模块**：
ArchDesign `Chart/` 下的一级目录名，同时决定模块构建目录；每个模块独立配置 `target/` 下的 `charts_path`。

**部署准备**：
一次从构建产物到容器环境的运行时工作会话，包含命名空间、一个或多个服务以及分析、生成、渲染和部署阶段。会话和日志不持久化，服务重启后失效。

**覆盖式重装**：
部署阶段固定执行再次渲染、卸载旧 release、释放其它 release 占用的同名资源、Helm 安装和工作负载就绪轮询。部署必须使用最新渲染结果签发的二次确认令牌。
