# 运维平台

运维平台统一管理基础设施运维能力。容器化、虚拟化和自动化工具是独立的平台域；构建、部署、环境和服务资源位于容器化平台域，Auto-UT 位于自动化工具平台域，虚拟化仅保留入口。

## 领域语言

**构建环境**：
构建任务必须选择的 Linux 远程环境。每个构建环境归属一个发布版本，固定使用 `huawei` 用户，并独立维护 IP、SSH 端口、密码、工作目录和系统架构。
_避免使用_：构建资源、编译机器

**容器环境**：
部署与容器运维使用的 Linux 远程环境。每个容器环境归属一个发布版本，唯一 OM 节点就是远程主机，固定提供 `sopuser`、`root` 两个 SSH 用户并分别维护密码，同时维护 OM 节点 IP、SSH 端口、工作目录、系统架构。业务面和管理面连接配置均可选；填写时需要同时提供完整 HTTP(S) 地址、账号和密码。
_避免使用_：部署资源、OM 环境

**发布版本**：
一年内的产品发布批次。版本编号与展示名称分别维护，例如 `R27C00` 展示为 `27A`，`R27C10` 展示为 `27B`；一个发布版本可以包含多个环境，每个环境只归属一个发布版本。
_避免使用_：工具链版本、配置版本

**系统架构**：
Linux 远程环境的指令集架构，取值为 `x86_64` 或 `aarch64`，界面分别显示为 x86 和 ARM。
_避免使用_：CPU 型号、CPU 信息

**连接测试**：
使用环境自身的 SSH 用户、IP、端口和密码验证能否建立 SSH 连接。构建环境固定使用 `huawei`；容器环境单次测试由用户选择 `sopuser` 或 `root`，批量测试使用 `sopuser`。连接测试不检查工作目录、系统架构、业务面、管理面或其他软件。

**CBB-Web-Dev 仓**：
参与构建的固定业务代码仓库。仓库地址由系统定义，构建任务只选择分支。
_避免使用_：可编辑业务仓、目标模块

**构建分支**：
分别绑定 CBB-Web-Dev 和 ArchDesign 的单一分支；未显式填写时使用 `master`。
_避免使用_：全局业务分支、多选分支

**构建任务**：
在一个构建环境中检出并构建 CBB-Web-Dev、ArchDesign 的一次运行时执行。单分支任务执行一组分支；双分支任务并发执行基准版本和验证版本，双方均成功后才对比 ArchDesign。任务状态和日志不持久化，服务重启后清空。

**构建产物**：
单分支构建成功后生成且可供后续部署选择的不可变结果。它记录构建环境、模块、两个仓库分支以及远端模块和 Chart 根目录。

**构建模块**：
ArchDesign `Chart/` 下的一级目录名，同时决定模块构建目录；每个模块独立配置 `target/` 下的 `charts_path`。

**部署任务**：
一次从构建产物到容器环境的完整运行时执行，包含执行方式、命名空间、一个或多个服务以及分析、生成、渲染和部署阶段。任务和日志不持久化，服务重启后失效；详细设计见[开发环境快速部署设计](superpowers/specs/2026-09-02-fast-deployment-design.md)。
_避免使用_：部署准备、部署会话

**快速部署**：
创建后自动执行分析、Chart 生成、Helm 渲染和部署的部署任务执行方式，中间不等待人工审阅 values。

**审阅部署**：
分析后暂停并允许查看替换结果和修改 values，经研发确认后继续执行的部署任务执行方式。

**部署工作负载**：
构建产物中可通过运行中 Pod 名前缀定位到的服务；能够与命名空间中的 `Deployment` 或 `StatefulSet` 同名匹配时一并展示工作负载类型。
_避免使用_：Pod、容器实例

**Pod 运行态快照**：
部署工作负载产生的临时运行实例信息，仅用于读取容器、镜像、阶段和 Ready 状态，不作为服务身份或部署目标。
_避免使用_：部署服务、工作负载

**覆盖式重装**：
部署阶段固定执行再次渲染、卸载旧 release、释放其它 release 占用的同名资源、Helm 安装和工作负载就绪轮询。

**服务资源**：
容器环境中按服务归集的实时 Kubernetes 资源集合。资源类型由 API Discovery 识别，服务归属由 Helm 清单和 Kubernetes 推荐标签派生；公共资源、未归属资源和集群级资源是无法唯一归属到单个服务的派生范围。具体接口和写入规则见 [服务资源工作区](container-resource-workspace.md)。

**Auto-UT 任务**：
从 Grafana UT CSV 中发现的单仓库自动修复执行。用户为一次报告统一指定基础分支，任务在本机独立工作目录中运行，只有测试修改门禁、完整 UT 和覆盖率目标全部通过后才通过 `codehub-cli` 上传提交并创建 CodeHub MR；运行规则与接口见 [Auto-UT 工作区](auto-ut-workspace.md)。

### AutoUtRepositoryMapping

保存 CSV 代码仓名称对应的 CodeHub clone URL。未保存映射时使用配置中的 URL 模板生成默认地址；保存后扫描和执行均优先使用持久化地址。

**手动 Auto-UT**：
默认执行方式。每完成一个关键阶段即暂停，由研发查看进度和关键事件后继续下一阶段。

**自动 Auto-UT**：
使用与手动方式相同的任务状态机，关键阶段间不暂停，持续运行至完成或需要外部处理。

**Auto-UT 每日定时**：
持久化的一组 Auto-UT 执行输入和北京时间，其中基础分支与立即执行使用同一输入来源。系统每天到点后通过同一任务创建入口启动自动模式，同一自然日只触发一次。
